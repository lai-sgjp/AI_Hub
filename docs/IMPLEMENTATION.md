# AI 酒馆实现约定

## 数据流

Compose 页面 → ViewModel → Repository（Room）/纯 Kotlin Engine → OpenAiClient。
core 不依赖 Android，群聊、导入、提示词和备份在 JVM 上测试。

启动先选择 World；世界保存背景、角色集合、世界书和用户人格模板。每个房间保存自己的世界 ID、API、角色 ID、剧情、人设、置顶记忆和摘要覆盖游标。
消息按序号排序，带角色 ID 和完成/生成中/中断/失败状态。
重生成创建同一房间的候选 StoryVersion，不增加房间。候选完整生成后原子激活；失败或取消保留候选并维持原活动版本。仅历史菜单的主动分支操作创建新房间。

群聊一次串行执行，第二角色读取第一角色完整回复。取消、断流、失败不进入下一角色。
摘要只处理游标后且近期窗口之前的完整消息，先成功再提交摘要及游标。

## 默认值

- 房间 1～8 位角色；每轮 1 位或 2 位；点名仅该角色。
- API 默认上下文 32768、最大输出 1024；温度 0.8；可配置流式开关。用户需按服务实际支持的长度设置。
- 通用 API 没有统一 tokenizer，使用 UTF-8 字节数加消息开销保守估计，显示为估算。
- 摘要阈值为可用输入预算 80%，默认也在累计 12 条未摘要完整消息后整理，保留最近 6 条；无法缩小到预算时停止并提示调整。
- 世界书仅常驻、关键词（不区分大小写）、优先级、启用；不执行导入脚本。
- 备份不含任何 API 密钥，以新 ID 恢复全部关联对象，禁止 ZIP 路径解压。
- 只支持 HTTPS 服务；开发构建可使用 HTTP 连接本地测试服务。

## 实施范围

简中、英文、日文界面及生成语言；文本聊天（未实现 Markdown 富文本渲染）、头像、深浅色、世界导览、故事入口、回复版本与剧情图。
不实现酒馆脚本/正则执行、提示词预设兼容、后台服务、同步、语音及图片生成。

新增世界、人格、大小记忆、记忆表和向量功能的详细边界见 `MEMORY-AND-SYNC.md`。SyncPort 是未来适配接口，V1 不含任何云端服务。

## 0.2.0 剧情版本与派生内容

`StoryVersion` 聚合拥有一条完整路线的消息、房间级事实、阶段记录及摘要游标。活动版本物化在原有消息/记忆记录中供聊天执行器读取，非活动版本保存在独立 version JSON 记录中；其父版本及切点保存在版本记录，不创建新房间。Repository.activate 在 Room 事务内捕获旧版本、替换活动消息/记忆/阶段及活动引用。用户明确提升为 world 的共享事实不被归档副本覆盖。

旧房间在恢复阶段幂等初始化默认版本；原有 parentId 保留，旧分歧位置无可靠证据时保持 null。备份输出 version=2，继续读取 version=1，恢复时对版本、内部历史、父版本、结局组和房间关联重映射。不导出密钥；可重建的翻译缓存恢复时丢弃以避免错误关联。

世界导览和入口依据世界/角色/世界书资料、选择身份和语言生成缓存键。长资料先分段整理，所有请求检查预算。原始世界/角色资料不被派生内容覆盖。首次内容服务操作显示 API 发送与额度提示；网络内容任务最多并发两项。历史消息翻译通过按钮请求，失败不写完整缓存。

主动分支调用配置的 API 命名，失败保留选择摘要，可重试或通过房间设置手动命名。完成回复后异步分析明确结局；仅同一故事根下的有效当前结局参与匹配。结局只是图上的共享终点，不共享时间线或记忆。拒绝的组记录在结局中，未来自动分析不得重新匹配该组；手动选择可以覆盖这一限制。

界面语言使用 Android 本地资源数组，兼容原有中文标签与动态模板。原始聊天只按需显示译文；新回复由提示词指定语言。ReplyText 同时用于流式显示、最终保存与历史提示组装，只处理当前角色的前导标签，不删除正文中的姓名。

## 0.2.1 内容任务与缓存

`ContentTasks` 按内容键合并在途工作，自动入口显式标记 automatic；失败与主动停止暂停自动任务。ViewModel 同时取消顶层任务、排队任务和 HTTP 协程，避免数据库读取完成后又创建请求。`AppSettings.autoContentPaused` 持久化暂停状态；主题、语言和额度告知改为事务内局部更新。

`ContentCompletion` 使用同一原始请求加 assistant 已完成前缀及继续指令，保留前缀末尾空格与 JSON 中断位置。每个原始内容请求最多 2 次临时错误重试、4 次长度续写（长资料导览有多个片段请求，各自计数）；退避 1 秒、2 秒，可取消。辅助 HTTP 客户端关闭连接自动重试，并以单次请求标记阻止网络库的隐藏跟随请求（如 503 + Retry-After: 0）；普通聊天保留原有连接恢复策略。进度不足、预算不足或永久错误立即停止。`ContentCache.status=partial` 只保存断点，默认 complete 兼容旧记录；完整结果验证后才写完整缓存。相同缓存键事务更新并清理重复记录。停止流式调用保存已收到内容，非流式未返回时没有可保存的正文；进程强杀只保证已落盘断点。

辅助请求采用一个固定 system 策略和一个 user 消息，在 user 消息内按原始资料、具体指令排列；角色聊天按房间 / 人设、当前角色完整设定、动态记忆及原有历史顺序组装。检索事实仍在历史之前，世界书筛选 / 优先级、摘要触发阈值及分支隔离均保留。长资料沿用原有整理策略，按源片段、服务地址及模型缓存整理结果，避免重复调用造成派生文本漂移；切换整理模型可生成新的摘要缓存。没有为缓存添加填充词、删减资料或压低摘要更新频率。

厂商前缀缓存与本机译文缓存互相独立。固定资料相同时请求前缀相同，并不保证厂商一直保留缓存或达到固定命中比例。普通聊天的生成失败 / 停止行为仍按消息版本处理；自动续写用于翻译、导览等辅助内容服务。
