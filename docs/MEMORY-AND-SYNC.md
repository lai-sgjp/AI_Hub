# 世界、记忆与扩展接口

## 世界与人格

启动后先选择世界。World 维护背景、可用角色、共用世界书和用户人格。
房间属于一个世界，创建时选择角色及用户人格。人格在房间内保存为快照，修改人格模板不追溯修改旧聊天。
角色定义可以被多个世界复用；房间消息、大小摘要和默认记忆表格按世界/房间隔离。

## 五层记忆

| 层 | 保存与使用 |
|---|---|
| 原始对话 | 所有完整/失败/中断消息保存在 Room，失败片段不会作为完整历史发送 |
| 小记忆 | 最近一批旧消息的阶段摘要，保留最近 6 条完整消息原文 |
| 大记忆 | 结合之前长期摘要与新阶段，累计人物关系、事件和未完成任务 |
| 记忆表格 | 类型、对象/属性、事实、来源消息范围、锁定、启用、共享范围 |
| 检索 | 当前世界和剧情内的关键词匹配，可叠加 embedding 余弦相似度，默认最多 8 条 |

输入估算达到可用预算的 80%，或启用定期整理且未摘要的完整消息达到 12 条时，在下一次角色回复前整理旧消息。调用同一个聊天 API，要求 JSON 中返回大小摘要和事实条目；JSON 解析、字段检查成功后，在同一个 Room 事务中保存摘要、覆盖游标、阶段记录和记忆表。

较长历史按预算分批，成功的批次可单独提交；后续批次失败不会回滚已经成功的批次。失败批次不推进游标，不删除原文。固定设定或单条消息放不进预算时停止并提示调整，不静默裁切。

“整理记忆”手动提取最近 12 条完整消息中的事实；自动阶段整理才会更新大小摘要。长篇单条消息可能需要增大上下文才能手动整理。

锁定条目不会被自动事实提取覆盖。普通条目按“世界 + 房间 + 类型 + 对象/属性”匹配更新，因此对象名建议写得具体，例如“银钥匙/持有人”。这是模型辅助提取，不保证事实绝对正确；记忆中心允许人工校正。

## 向量化

每个 API 配置可选 embedding 模型，使用相同的基础地址与密钥调用 `/embeddings`，不假定聊天模型本身能输出向量。

- 自动提取新记忆后尝试批量向量化；手动整理或“重建向量索引”也可生成索引。
- 本机保存向量，在本机计算余弦相似度；查询文本发送到 embedding 服务。
- 使用基础地址和 embedding 模型组合标识向量空间，不混用不同模型的向量。
- 编辑事实后清空该条旧向量；恢复备份后也清空向量，需重新索引。
- 生成查询向量失败时显示提示，并使用关键词检索；向量接口错误不让已保存记忆消失。
- V1 使用线性检索，适用于个人规模的记忆表；未部署外部向量数据库。

## 分支

历史编辑或重新生成创建新房间分支，清空新分支大小摘要。只复制来源完全位于分支切点之前的剧情事实，避免旧分支的未来事件污染新剧情。世界共享记忆是用户主动开启的跨房间事实，因此所有分支均可召回；默认不开启。

## 格式兼容

支持 SillyTavern V1/V2/V3 `chara` PNG tEXt 元数据和 JSON 卡；PNG 块校验、长度和大小受限制。支持世界书数组/对象条目结构、关键词、常驻、启用和优先级。

不是 SillyTavern 运行时，不执行角色卡中的 JavaScript、正则脚本、插件或宏脚本。只替换 `{{char}}` / `{{user}}`。未应用字段列入导入报告；V3 卡按独立格式导入，不伪装成 V2。
没有宣称兼容某款“数据库记忆插件”的私有文件格式；本版本实现的是原生数据库记忆能力。未来接入具体插件格式应增加独立转换适配器和测试样本。

## 云同步预留

`core/SyncPort.kt` 定义 pull(cursor) / push(payload, expectedRevision)，SyncEnvelope 携带 schemaVersion、Snapshot、revision、cursor、deletedIds。

- V1 仅定义接口，不存在网络同步实现、账号或自动上传。
- 所有持久对象使用稳定 UUID；JSON 新字段提供默认值，Room 导出 schema 以供后续迁移。
- Snapshot 不含密钥。SecretStore 只在 Android 本地使用，不属于同步载荷。
- 手动 BackupCodec 恢复会重映射 UUID，适合导入副本。未来同步适配器必须保留 UUID，不能调用“恢复副本”流程。
- expectedRevision 为后续乐观并发控制保留；未来实现需要明确服务端鉴权、冲突界面、删除传播及增量策略。本版本没有伪实现这些功能。
