# 0.2.1 翻译控制与缓存验证

日期：2026-09-11。本次仅本地代码、私有 APK 与验证记录交付；未发布、推送或调用真实厂商 API。

## 修复内容

1. 固定位置的“停止翻译”取消顶层任务、HTTP 请求及信号量队列；`autoContentPaused` 保存在本机。自动翻译在页面重新进入、滚动和 ViewModel 重建后保持暂停，完整本地缓存仍可读取。手动重试单项不会隐式恢复整个批次。
2. 临时网络错误 / 5xx 最多 2 次重试，等待 1 秒、2 秒；网络拦截器阻止同一调用发送隐藏的后续请求（额外用例验证 503 + Retry-After: 0 从实际 6 次收敛为 3 次），普通聊天保留原有连接恢复策略；鉴权、429、格式错误立即停止。失败耗尽后暂停自动内容任务；普通 Compose 重组不能再次开启请求循环。
3. 长度截断最多自动续写 4 次，加首次共 5 段；重试预算在整个任务内共享，因此每个原始内容请求最多 7 次 HTTP 尝试。长资料导览可包含多个片段请求，各自计数，统一受停止操作控制。每次检查完整原文 + 已生成前缀 + 继续指令的预算，不为续写丢弃原文。超限、无进展或预算不足时停止。
4. 长度断点与流式主动取消的已收到部分以 partial 状态保存，再点原翻译按钮继续。前缀末尾空格、未结束 JSON 字符串均保留；短词正常重复不去重。未完成结果不触发完成回调、不写完整译文缓存。非流式返回正文前不能保存未收到文字，进程强杀只保证已落盘断点。
5. 合并同内容同语言的并发任务；缓存按键事务更新，旧重复记录在更新该键时去重。旧 complete 缓存兼容读取；入口文本缓存不再受随机本地成员 ID 影响，生成入口在重进世界页后仍可从缓存恢复。

## 厂商缓存与效果边界

- 辅助请求使用标准 system → user 结构，保持“稳定策略 + 完整源资料”前缀，把任务 / 目标语言指令放在 user 消息末尾。导览与入口使用同一份未修改资料时可共享前缀。
- 聊天保持房间 / 人设、完整当前角色卡在前，变化的检索事实 / 摘要在后；历史依旧位于这些设定和记忆之后。所有角色字段、占位符替换、有效世界书、优先级、近期历史、检索与版本隔离逻辑保留。
- 未增加填充文本，未删减角色卡或相关记忆，未调整摘要触发阈值。原有长资料整理策略保持不变；只缓存相同源片段在相同服务和模型下的整理结果。切换模型会使用新的片段缓存键。
- 以上验证的是输入保留和前缀一致性，不能替代真实模型对剧情质量的验证，也不保证固定命中率。DeepSeek 的缓存要求从开头匹配相同前缀，服务端缓存按尽力而为方式保留；短资料、首次请求和缓存淘汰仍可能不命中。[DeepSeek 官方缓存说明](https://api-docs.deepseek.com/guides/kv_cache/)
