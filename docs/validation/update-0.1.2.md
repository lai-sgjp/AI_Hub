## 发现与修复

首次升级仅验证磁盘数据完整时曾通过，但设备 UI 测试随后发现 CursorWindow 不能读取大型角色记录。
修复分段读取后，大记录测试通过；全套测试进一步发现全尺寸头像造成 192 MB 堆内存不足。
新内置头像缩略化后，10 项设备测试全部通过。被拒绝的中间 APK 移至 `.tools/`，不作为交付。

升级检查现在允许新增记录，并核对所有旧记录、加密凭据、包初始化标记及进程存活。
原先只比较整个数据库相等的检查既误报新增世界，也不能证明界面可用；因此保留设备测试作为独立验收。

## 边界与交付自评

未使用实体手机或真实厂商 API；模拟器成功不等同于所有厂商安装器、Android 版本和内存规格验证。
旧用户更新时不能卸载 App。未实现对相同 bundle id 的内容覆盖更新，以保留用户编辑。

使用 agent-self-evaluation 五轴复核，平均 4.4/5：

| 维度 | 分数 | 证据与局限 |
|---|---|---|
| 准确性 | 4 | APK 身份、数据库计数及测试可复核；只覆盖 API 35 模拟器 |
| 完整性 | 4 | 覆盖更新、首次安装、无密钥安装及实际崩溃均处理；尚无实体手机验证 |
| 清晰度 | 5 | 明确完整 APK、保留数据更新与差分下载的区别 |
| 可操作性 | 5 | 直接交付本地 APK，并保留复现脚本 |
| 简洁性 | 4 | 最终答复保持简短，详细失败过程保留在本文便于审计 |

后续最有价值的验证是用户实体手机覆盖安装及原 API 配置实际请求。无需为此阻止本地 APK 交付。
自检：用户可直接取得经过模拟器验证的 APK，并明确知道尚未覆盖的设备范围。
